# Developer context — core

Актуальность: 2026-11-08. Minecraft 1.21.1, Java 21. Имя `core`, mod ID `faustcore`,
Java package `com.faust.core`, версия 1.4.0. Документ самодостаточен: локальные
`des-doc.md` и `work_notes/` для интеграции не нужны. Корневые инструкции Agents.md
встроены ниже и должны обновляться вместе с оригиналом.


## Актуальные правила 1.4 (2026-11-08)

Этот раздел заменяет противоречащие ему правила предыдущих версий ниже.
Начальный потенциал всех характеристик — 5; покупка +1 и максимум 20 прежние.
На главном экране K убраны краткие описания. Внутри характеристики описана её
прокачка, а подсказки узлов показывают конкретные бонусы из statBonuses.json:
величину за уровни, единицы/проценты, максимум и ограничение только бегом.
Прогресс требований и полоска слева ограничены 100%; настоящие счётчики сохраняются.

Пассивные характеристики по-прежнему требуют отдельных открытых навыков.
Новые требования по умолчанию:

| Узел | Уровень | Практика | Родитель |
|---|---:|---|---|
| Урон | 5 | 100 заряженных попаданий по враждебным мобам | — |
| Скорость бега | 5 | 1500 м бега | — |
| Скорость атаки | 8 | 150 попаданий | Скорость бега |
| Здоровье | 5 | 100 фактически потерянных HP | — |
| Запас выносливости | 8 | 2500 м бега | Здоровье |
| Бонус брони | 8 | 1500 м бега в броне | Ношение железной брони |
| Удача | 5 | 15 чтений книг | — |
| Скорость ломания | 5 | 500 установленных блоков | — |
| Дальность взаимодействия | 10 | 1500 установленных блоков | Скорость ломания |

Щит: уменьшение износа теперь 10%, отключения — 15%. Экономный блок открывается
на уровне 8 после 60 блоков и навыка ухода за щитом; расход остаётся 2 → 1.
Лук расходует 2 ед.: ловкость 5 + 30 выстрелов открывает −1, ловкость 10 +
150 выстрелов и первый узел открывает ещё −1 (итого 0). Арбалет расходует 1;
сила 5 + 30 выстрелов открывает −1. Булава расходует 2; сила 10 + 50 заряженных
попаданий булавой и узел урона открывает снижение до базовой стоимости удара.
Платёж взимается за выстрел, включая весь залп арбалета, а не за зарядку.

При нуле включается сохраняемый режим истощения: шкала красная, запрещены спринт,
удары, выстрелы и щит. Обычные прыжки доступны, даже при нуле. Выход при stamina.exhaustionRecovery = 10,
но не выше доступного максимума (усталость не создаёт безвыходную блокировку).
Навык «Быстрое восстановление»: Constitution 10, 5000 м бега и Second Wind;
снижает порог вдвое, до 5 по умолчанию. stamina.exhaustionLock = 0 отключает
длительный режим; нулевой запас всё равно запрещает действия. Creative/Spectator
и stamina.enabled = 0 сохраняют исключение.

Спринт развивает Constitution через actions.constitution_run: 0.01 опыта/м,
до общего trainingMultiplier и коэффициента потенциала. Плавание развивает
Constitution с множителем skills.constitutionSwimMultiplier = 2 относительно
ставки actions.constitution_swim (также 0.01). Считаются реальные метры из
vanilla stats, с лимитами runMetresPerMinute и swimMetresPerMinute = 200.
Базовый бег расходует stamina.runCost = 0.1 ед./с; броневая надбавка
равна stamina.armorCost = 0.25 × вес сверх переносимого. Прыжок при беге
стоит 0.5 ед. (stamina.sprintJumpCost) плюс 0.05 ед. за единицу веса брони
(stamina.jumpArmorCost).
Все четыре ставки уменьшены вдвое относительно 1.3. «Второе дыхание»
восстанавливает runCost × stamina.secondWindMultiplier (1.5), то есть
0.15 ед./с при базовой стоимости бега 0.1 ед./с.
Быстрое плавание после stamina.swimDelaySeconds = 3 непрерывных секунд расходует
stamina.swimCost = 0.4 ед./с. Противотечение оплачивается дополнительно.

Положение выносливости привязано к фактической отрисовке hud/air и hud/air_bursting
через GuiGraphics.blitSprite: при пузырьках шкала поднимается над их верхним краем,
после исчезновения возвращается. Учитываются те же спрайты из других namespace;
произвольный собственный HUD другого мода требует адаптера. Это не проверка
«только под водой»: остаточный воздух вне воды тоже учитывается. Клиент передаёт
факт отрисовки серверу; сервер дополнительно проверяет vanilla-условия и число
пузырьков. При воздухе восстановление, включая Second Wind, умножается на
stamina.airRecoveryMultiplier = 0.5. Полёт isFallFlying и поднятый щит полностью
останавливают восстановление, включая Second Wind. Просто надетые элитры не мешают.
Протокол C2S swim_input теперь передаёт forward + airVisible; NeoForge protocol = 3,
обновлять нужно и клиент, и сервер.

При успешном пропуске ночи спавшие игроки получают fatigue = −fatigue.sleepReserve
(по умолчанию −5). Не спавшие игроки сохраняют свою усталость. Вставание до пропуска
ночи не даёт резерва; fatigue.resetAfterNight = 0 отключает правило. Отрицательная
усталость сохраняется в мире и расходуется до нуля; до перехода в положительные
значения она не уменьшает и не увеличивает максимум выносливости. Обычное заполнение
выносливости не выдаёт резерв. Сон без пропуска, костёр и сладкая еда не повышают
уже отрицательную усталость до нуля.

Миграция сохраняет затронутые конфиги в migration-v1.4, добавляет новые параметры
и узлы, усиливает требования стандартных узлов и снижает щитовые бонусы. Старый
стандарт initialCap=10 заменяется на 5, другие пользовательские значения сохраняются.
Купленные прибавки к потенциалу остаются, базовая часть становится 5; ручные override
и изученные способности не сбрасываются. Пользовательские узлы и ставки сохраняются.


Проверка 1.4: `./gradlew.bat build --offline -PcoreModMenuRepository=<локальный Maven>`
успешна для обоих загрузчиков: 126 проверок модели, 83 новых проверок 1.4 и
33 проверки команд (242 всего). Dev-клиенты обоих загрузчиков загрузили ресурсы
без ошибок Mixin; после проверки запущенные тестовые клиенты остановлены.
Fabric dedicated server дошёл до требования EULA, она не принята. NeoForge dev
dedicated server загрузил мир до сообщения Done (dev-запуск не потребовал EULA).
Тестовые процессы остановлены. Полный игровой прогон сценариев ещё не выполнен.

Для проверки в Survival с разрешёнными командами: `/core fatigue clear @s`,
`/core stamina set @s 0` — красное истощение с обычными прыжками;
`/core stamina set @s 10` — выход из режима. С выданным через
`/core ability grant @s faustcore:resilient_recovery` навыком порог станет 5.
Проверяйте воздух в воде и сразу после выхода из воды, полёт на элитрах,
лук/арбалет/булаву и сон двух игроков (один спит, другой нет).
`/core fatigue set @s -5` позволяет проверить переход резерва через ноль;
значение ограничивается настройками sleepReserve и maximum.

## История правил до 1.4

Последние уточнения: ускорение ограничено 200% (maximumGrowth≤2). Текст панели,
подсказок и HUD рисуется без тени. Броневой расход armorCost теперь 0.5: полный
незерит без открытых способностей переносимости брони (W=14, H=0) расходует
7 ед./с сверх базового расхода бега. При нулевой выносливости спринт и атаки
недоступны. Бежать снова можно при положительном запасе, атаковать — когда
хватает единиц на удар. Ожидание полного восстановления удалено в 1.3;
устаревший stamina.exhaustionLock больше не ограничивает эти действия.
Старый стандартный armorCost=0.1 автоматически повышается до 0.5; явно отличающиеся
пользовательские ставки сохраняются. Перед этой миграцией stamina/progression
копируются в migration-v1.1-resource. Для работающего клиента/сервера нужен перезапуск
с новым JAR: перекомпиляция проекта не обновляет уже загруженные классы.


## Постоянные бонусы, иконки и настройки из меню модов

Constitution даёт +1 максимальный HP за уровень (на уровне 20 — 40 HP при vanilla
базе 20). Дополнительно сохраняется +0.2 выносливости за уровень. Повышение
максимума не является бесплатным лечением; при возрождении максимум применяется
до восстановления здоровья, при загрузке сохраняется записанное здоровье.
Intelligence даёт +0.01 к vanilla Luck за уровень, максимум +0.2. Это единицы
атрибута Luck, не универсальный шанс дополнительной добычи 20%.
Building даёт +1% скорости разрушения за уровень и +1 блок к дальности
взаимодействия с блоками и сущностями каждые 10 уровней. Бонусы деревьев добавляются
отдельно. Strength и Dexterity сохраняют свои бонусы урона и скорости бега,
Defense — переносимости брони и щитовых способностей.

Все ставки редактируются в skills.json: healthPerLevel, luckPerLevel, luckMaximum,
reachEveryLevels, reachPerStep, breakingPerLevel, breakingMaximum.
Визуальные ступени иконок — 0, 5, 10, 20 (iconTier1/2/3); используются исходные
locked_0/8/16/24.png. Всего перенесены 26 PNG (24 иконки + панель и вкладки),
побайтово без изменений. Лицензия и NOTICE включены в JAR.

**Меню модов → core → Настройки** открывает редактор всех разделов конфигурации:
числа, действия, интеграции, HUD и массивы деревьев. Это редактор JSON с выбором
разделов и прокруткой, а не набор слайдеров. Черновики сохраняются при переключении
разделов и изменении размера окна. Кнопка «Сохранить» проверяет всю связанную
конфигурацию и записывает один раздел через временный файл и атомарную замену.
Ошибочный JSON/диапазон/цикл дерева ничего не заменяет. Максимальная длина раздела
в сетевом редакторе — 8192 символа; большие конфиги можно редактировать файлами.

NeoForge использует встроенную кнопку настроек списка модов. Fabric требует
**Mod Menu 11.0.3** для 1.21.1 (не обязателен для самого core; в dev runtime
подключается автоматически). Официальный API:
https://github.com/TerraformersMC/ModMenu/blob/v11.0.3/src/main/java/com/terraformersmc/modmenu/api/ModMenuApi.java
В существующую сборку Fabric Mod Menu устанавливается отдельно.

В главном меню редактируются локальные файлы экземпляра. В мире редактируются
серверные настройки: сохранять может оператор permission level 2 или владелец
одиночного мира. Прочие игроки могут просматривать настройки, но сервер отвергает
изменения. Проверка полномочий выполняется сервером для каждого запроса, независимо
от состояния кнопки клиента. Payload config_edit передаёт только фиксированное имя
раздела и JSON, config_result — разрешение и результат. Произвольные пути запрещены.
Клавишу открытия по-прежнему меняют в стандартном управлении Minecraft.


## Изменения 1.2 — актуальные правила (2026-11-08)

Этот раздел заменяет прежние ставки бонусов. Strength даёт +1% урона/L,
Dexterity — +1% скорости атаки/L и +1% скорости **только спринта**/L.
Constitution — +1 HP и +1 выносливости/L. Intelligence — +0.01 Luck/L до +0.2.
Building — +1% ломания/L, +1 дальности/10L, максимум дополнительной дальности +3.
Defense — +1 брони/2L, помимо прежней переносимости и способностей щита.

Все бонусы атрибутов задаёт **statBonuses.json** (доступен и из меню модов).
Пример одной дополнительной записи в массиве — Dexterity даёт +1 HP/L:

```json
{"id":"dexterity_health","skill":"dexterity","attribute":"minecraft:generic.max_health","perLevel":1}
```

Необязательные поля: operation (`add`, `multiply_base`, `multiply_total`),
everyLevels (по умолчанию 1), maximum (индивидуальный потолок бонуса), sprintOnly.
Для +1% применяется perLevel=0.01 и operation=multiply_base; для дальности —
everyLevels=10, perLevel=1, maximum=3. Встроенные строки можно изменять, удалять,
добавлять. ID должны быть уникальны. Атрибут должен существовать и быть доступен
игроку; неизвестные атрибуты не применяются. Удалённые правила снимают модификатор
при пересчёте. Неиспользуемые старые числовые stat-поля skills.json считаются legacy;
для этих атрибутов используйте именно statBonuses.json. Скорость ломания остаётся
в skills.json, выносливость — stamina.json, условия и эффекты узлов — abilities.json.

Эффекты открываемых способностей дерева усилены ×10; щитовые скидки ограничены
95% согласно существующему ограничению. Second Wind заменён специальным эффектом:
пассивное восстановление **всегда** равно stamina.runCost (0.2 ед./с), в том числе
при расходе. Поэтому бег без брони/лишней нагрузки не истощает запас с этой
способностью; броня, удары и плавание остаются дополнительными расходами.
Базовый опыт действий удвоен через progression.trainingMultiplier=2; счётчики
условий способностей не удваиваются. Отображаемый бонус предела по-прежнему ≤200%.
Выше предела slowdown=0.5 вместо 0.25: штрафная составляющая удвоена.

Каждый ближний удар, включая промах, стоит stamina.attackCost=1. При нехватке
запаса удар по сущности отклоняется сервером; одна атака не оплачивается повторно
пакетом анимации. Взмахи при добыче блоков не являются отдельной платой за удар.
Creative/Spectator и отключённая выносливость сохраняют прежнее исключение.

Шкала расположена над голодом; числа всегда округляются вниз до целых.
client.hudX/hudY — смещения от этого якоря. Усталость остаётся чёрной частью справа.
Обычный костёр снимает ровно 1 ед. каждые 25 с отдыха: скорость прежняя 0.04 ед./с,
остаток времени сохраняется между подходами. Сон восстанавливает постепенно.
Костёр душ добавляет 0.04 ед./с при нахождении рядом, независимо от неподвижности;
огонь душ — 0.1 ед./с, пока игрок горит после контакта с ним. Если одновременно
действуют несколько источников, их изменения суммируются. Все ставки настраиваемы
в fatigue.json. Текущая причина горения душ сохраняется, пока огонь не потушен.

Миграции сохраняют конфиги в migration-v1.2 и migration-v1.2-environment перед
изменением правил. Для применения нового кода замените JAR и перезапустите игру.
Подсказки панели теперь рисуются последними и выше карточек/вкладок; тень выключена.


## Актуальные правила 1.3 (2026-11-08)

Этот раздел заменяет прежние правила пассивных бонусов и истощения.
Характеристики сами по себе не дают статов: каждый бонус открывается отдельным
узлом дерева (уровень 1 и реальное действие). Здоровье, выносливость, скорость
спринта, скорость атаки, урон, удача, броня, дальность и ломание — отдельные узлы.
statBonuses.requiresAbility указывает нужный узел; для новой строки без этого поля
создаётся собственный стабильный узел training_<id>. Эффект начинает действовать
после открытия узла и масштабируется уровнем характеристики, как ранее.
Удалены исходные старые узлы остальных веток; сохранены вся ветка защиты,
Second Wind и пользовательские/сторонние навыки. Старые открытые ID сохраняются
в данных, но удалённые узлы больше не дают эффектов.

«Ношение брони до железной» позволяет бегать без броневой доплаты в комплекте до
железного включительно; следующий узел — до незеритового. Носить более тяжёлую
броню можно, но она требует дополнительной выносливости. «Экономный блок щитом»
снижает плату за успешный блок с 2 до 1; само удержание не расходует ресурс,
но **полностью останавливает восстановление**, включая Second Wind.

Удар обычным оружием стоит 1, булавой 2, успешный блок щитом 2. Прыжок в спринте
стоит 1 + вес брони ×0.1; без брони — 1. Настройки: stamina.attackCost, maceCost,
shieldCost, sprintJumpCost, jumpArmorCost. При нехватке ресурса действие
отклоняется. Нулевой запас запрещает атаку, но **ожидать полного восстановления
для возобновления бега больше не нужно**. Как только есть запас, можно бегать;
прыжок/атака/блок требуют оплатить свою полную стоимость.

Constitution обучается от разности HP до и после успешного урона, то есть ПОСЛЕ
брони/сопротивлений/прочего снижения. Полное поглощение щитом/absorption не даёт
потери обычных HP. Порог skills.damageMinimumHP=2: отдельный урон меньше 2 HP не
считается; урон не округляется вверх до двух и мелкие попадания не суммируются.
Все источники фактического урона по-прежнему разрешены.

HUD не содержит текста: ряды кружков 8×8 над голодом, 10 кружков на ряд,
один кружок=2 единицы с половинками. Дополнительный максимум добавляет ряды вверх.
Белые сегменты — запас, пустые — потраченный доступный запас, чёрные — усталость.
В Creative и Spectator HUD скрыт. Новый собственный спрайт stamina_dots.png не
заимствован из JustLeveling; его лицензия — основная лицензия core.

sweetFoods.json задаёт снижение усталости отдельно для каждого item ID:
например cookie=1, pumpkin_pie=3, honey_bottle=2, apple=1, ягоды/арбуз=0.5.
Можно удалять и добавлять типы еды. Снижение происходит после завершённого
употребления, а не при начале анимации, не поднимает сам запас выносливости и не
уходит ниже нуля. Блочное поедание торта этим item-hook не охватывается.

При обновлении конфиги сохраняются в migration-v1.3, затем обновляются узлы,
связи и новые настройки. Явно пользовательские/сторонние узлы не удаляются.
Для проверки создайте отдельный Survival-мир; проверьте полные/половинные кружки,
увеличенный максимум, Creative, прыжки с разной бронёй, булаву и обычный удар,
блок с/без узла, запрет восстановления при удержании, реальные 1/2 HP урона,
сладкую еду и отсутствие бонуса до открытия соответствующего навыка.
Полная ручная игровая приёмка этой версии пока не выполнена.

## Идея серии и утверждённые правила

Core — умеренная базовая прокачка для серии модов. В будущем игрок выбирает один
путь (например, мага, вампира или ведьмака), каждый путь — внешний мод, зависящий от
core. Ядро не зависит от модов путей. Их механик в этой версии нет.

Шесть основных навыков: Strength / Сила (`strength`), Constitution / Телосложение
(`constitution`), Dexterity / Ловкость (`dexterity`), Defense / Защита (`defense`),
Intelligence / Интеллект (`intelligence`), Building / Строительство (`building`).
`defence` из обсуждения не является вторым ID. Magic и Luck исключены. Отдельной
покупаемой базы характеристик и дополнительных Mining/Athletics нет.

Навыки растут от серверно подтверждённых действий. Мягкий предел индивидуален;
выше него практика продолжается с замедлением. Повышения пределов оплачиваются
vanilla-уровнями опыта; каждое следующее повышение дороже с учётом всех веток игрока.
Уровень 20 ограничивает требования узлов дерева; мягкий предел теперь также не выше 20, но сам навык может расти выше него.
Способность требует одновременно уровня, игрового достижения и предшественника.
Игрок открывает её явно; отдельной валюты способностей нет. Действия до открытия
предшественника учитываются. Повторное открытие не добавляет бонус.

Выносливость мала и быстро восстанавливается. Расходуется на настоящий бег в броне
сверх допустимой нагрузки и активное плавание против течения. Простое ношение
брони, ходьба, атаки, щит, парирование и уклонение сейчас ресурс не расходуют.
Фактическая трата накапливает усталость, уменьшающую доступный максимум до отдыха.
Усталость уходит постепенно во сне и при неподвижном отдыхе у зажжённого костра.
Смерть, reconnect и смена измерения её не снимают. Конституция развивается от всех
источников фактической потери HP; намеренные тренировочные циклы разрешены по
прямому решению пользователя. Отдельных антиабуз-лимитов для неё нет.

## Реализованные действия и значения по умолчанию

Числа доступны в config/faustcore. Creative и Spectator исключены из обучения.
Нулевой/отменённый урон не даёт опыт. Единицы X — опыт действий, не vanilla XP.

| Действие | Навык | X и счётчик условия |
|---|---|---|
| Заряженный прямой удар по враждебному мобу | strength | 1 X/потерянный HP, максимум 10 за удар; counter hits +1 |
| Фактическая потеря HP от любого источника | constitution | 1 X/HP; counter damage_taken +HP, включая смертельный урон |
| Самостоятельный бег по земле | dexterity | 0.05 X/м; run_metres +м; до 200 м/мин |
| Тот же бег в броне с положительной нагрузкой | defense | 0.05 X/м; armor_metres +м, включая освоенную броню |
| Щит блокировал атаку враждебного моба | defense | 1 X/предотвращённый HP, до 5 за блок и 20/мин; blocks +1, интервал 20 тиков |
| Открытие написанной книги | intelligence | 5 X; books +1; пауза 30 с |
| Завершённое зачарование | intelligence | 10 X; enchants +1 |
| Сделка с жителем | intelligence | 3 X; trades +1 |
| Первый вход внутрь конкретной сгенерированной структуры Minecraft | intelligence | 20 X; structures +1 |
| Успешная установка блока | building | 1 X; placed +1 |
| Крафт предметов | building | 1 X/результирующий предмет; crafted +количество |

Для размещения и крафта общий лимит 300 единиц/мин на игрока. Размещение берётся из
vanilla ITEM_USED для BlockItem; неуспешная установка не должна выдавать эту
статистику. Крафт — ITEM_CRAFTED, торговля/зачарование — соответствующие CUSTOM stats.
Чтение означает открытие книги, а не доказанное прочтение её текста. Повтор той же
книги после паузы допустим. Структуры определяются по попаданию в их части;
идентификатор экземпляра: измерение + registry ID + стартовый чанк.

Сила: не считаются стрелы, периодический урон, взмахи в воздух, союзники, вторичные
попадания sweep. Vanilla charge ≥0.9 фиксируется до сброса заряда. Бюджет цели
ограничен её maxHP при первом зачётном контакте; лечение не восстанавливает его.
Специальное определение спавнерного происхождения не реализовано, отдельного
коэффициента спавнера нет. Для Building история размещений мира не ведётся:
повторная установка может обучать в пределах лимита. Это ограничения текущей
версии, а не обещанная защита от любых ферм.

Малые автоматические эффекты: strength +0.2% ближнего attack damage/L, до +10%;
dexterity +0.1% скорости при беге/L, до +5%; building +1% скорости разрушения/L без прежнего ограничения +15%. Constitution добавляет 1 к базовому запасу Stamina за уровень. Defense
повышает допустимую нагрузку брони. Интеллект сейчас даёт эффекты через дерево.
Бонусы узлов суммируются с указанными малыми эффектами как разные явные вклады;
копии исходных пассивов JustLeveling одновременно не работают.

## Формулы (редакция 1.1)

Начало: L=0, x=0, C=10. Требование практики для следующего уровня T(L)=100+20L.
Ниже предела множитель min(2, C/max(1,L)): C=10, L=5 → 200%; C=15, L=5 → также 200%.
На нулевом уровне знаменатель 1. На пределе и выше сохраняется замедление
1/(1+0.25×(L−C+1)), без жёсткой остановки практики. Событие разбивается на границах
уровней, на каждом участке множитель пересчитывается; дробный опыт сохраняется.
Игровой L не ограничен 20; есть технический предел int.

Покупка повышает только выбранный C на 1 и запрещена при C=20. Цена в целых
vanilla-уровнях: ceil(n + m/5), где n — выбранный текущий C, m — сумма текущих C
всех зарегистрированных навыков. Это согласованная трактовка пользователя, не
сумма натренированных L. По умолчанию шесть C=10 дают 22 уровня за первую покупку.
Strength → Building → Strength: 22, 23, 24 уровня; пять последовательных покупок
Strength: 22, 24, 25, 26, 27. Проверка и списание серверные; giveExperienceLevels
сохраняет долю полосы vanilla XP. G и числа покупок остаются в сохранении для
истории, но экспоненциальной цены от G больше нет. Покупка не выдаёт практику.

Выносливость: базовый B=20+0.2L_constitution+бонусы дерева. S — текущий запас,
F — абсолютное число единиц усталости, а не доля. M=max(minimum,B−F), по умолчанию
minimum=4, F ограничена 16. Расход D добавляет 0.05D единиц F, только за реально
оплаченную часть. Уменьшение S при снижении M не вызывает дополнительной усталости.
После 1.5 с без расхода регенерация 4 S/с плюс способности. Сон снимает 0.2 F/с,
костёр 0.04 F/с; считаются реальные тики отдыха, не часы пропущенной ночи.

Нагрузки частей брони прежние: leather 1, chainmail 2, iron 2.5, golden 2,
diamond 3, netherite 3.5; fallback 2, точный item ID переопределяет материал.
H=2+0.5L_defense+бонусы. Фактический бег при W>H расходует 0.5×(W−H) S/с.
Встречное плавание — 1×встречная составляющая потока S/с, порог 0.05.
Сервер проверяет плавание, поток, взгляд, отсутствие транспорта и свежий сигнал
вперёд от клиента (≤20 тиков). При исчерпании ресурса sprint снимается на сервере
и прогнозируется клиентом; обычное управление остаётся. Полная защита от клиента,
подделывающего vanilla-движение/намерения, не заявлена.

HUD: единая полоска. Текущий S — цветная часть слева, незаполненный доступный
запас — тёмно-серый, занятый F участок справа — чёрный. Чёрная часть не является
потраченным S: её освобождает отдых. Отдельного текста, процентов и второй шкалы
усталости нет. Числа обозначают S / B. В панели кошелёк и цена показаны в vanilla-
уровнях, практика — процентом, не сырыми очками vanilla XP.

## Конфигурация и изменение баланса

Корень — стандартный `<экземпляр Minecraft>/config/faustcore/`. В обычном лаунчере
это .minecraft/config/faustcore; в отдельных сборках — их собственный config.
Текущий код создаёт JSON-файлы с полными значениями по умолчанию при первом запуске.
Комментарии внутрь JSON не добавлять. Удаление файла приводит к созданию defaults,
но повреждённый существующий файл не перезаписывается автоматически.

| Файл | Назначение / единицы |
|---|---|
| progression.json | levelBase/levelSlope в X; initialCap/capStep в уровнях; maximumCap (не выше 20), costDivisor=5, maximumGrowth≤2; slowdown — коэффициент замедления |
| actions.json | action ID → skill, xp за единицу действия, counter; xp=0 сохраняет достижение, но не добавляет X; удаление действия выключает его |
| skills.json | Автоматические процентные бонусы — доли (0.1=10%); damage/hit/shield ставки в HP; интервалы с суффиксом Ticks — тики; readCooldownSeconds — секунды; runMetresPerMinute — метры; blockMaximumPerMinute — число предметов/блоков |
| abilities.json | Массив узлов: id, skill, level 0…20, counter, amount, parent (пусто для корня), effect, value |
| stamina.json | enabled 0/1; base в S, constitutionPerLevel в S/L, regeneration в S/с, delaySeconds в секундах; armorCost в S/(с×вес), waterCost в S/с на единицу потока |
| fatigue.json | enabled 0/1; perSpentFraction — единицы F на потраченную единицу S; maximum/minimum — единицы, minimum — нижняя граница M; sleepPerSecond/campfirePerSecond — ед./с; campfireRadius — блоки (до 16) |
| armor.json | веса материалов, точные item ID, fallbackWeight, baseCapacity, capacityPerLevel — условные единицы нагрузки |
| integrations.json | Резерв настроек внешних адаптеров. weaponDefenseEnabled пока не подключает боевой мод и не выдаёт оружейную защиту |
| client.json | hud 0/1, hudX/hudY/hudWidth — GUI-пиксели. Привязка K регистрируется штатно через KeyBindingHelper (Fabric) / RegisterKeyMappingsEvent (NeoForge), сохраняется в options.txt и не присылается сервером; остальные параметры HUD пока серверные |

Встроенные effect ID: damage, speed, breaking (доли), regeneration (S/с), stamina
(S), capacity (нагрузка), shield_durability, shield_recovery (доли скидки).
Каждая щитовая скидка ≤0.95; суммарная скидка также ограничивается 95%.
Сторонний namespaced effect может храниться в конфиге без установленного обработчика,
но не действует до его регистрации. Существующие неизвестные ID прогресса и узлов
сохраняются; отключение/удаление узла из конфигурации выключает его эффект без
удаления записи о достижении.

Все числа баланса вынесены в конфиги; размер протокольного буфера, 20 тиков/с,
vanilla cooldown щита 100 тиков и ограничения числового представления — технические
или vanilla-константы, не новые параметры баланса.

Отключение stamina.enabled приостанавливает расход, ограничения, регенерацию и
изменение усталости ядром. При fatigue.enabled=0 M=B, F не растёт и не убывает,
её история сохранена для повторного включения. HUD отключается независимо.

`/core reload` требует permission level 2. Кандидат валидируется целиком: числа,
известные параметры, ID, родители, отсутствие циклов и межнавыковых родителей.
Невалидный reload оставляет предыдущий баланс. Уже оплаченные покупки не
переоцениваются. Уровень сохраняется, доля текущего уровня мигрирует при изменении
T. Порог, использованный при сохранении, хранится в Track.threshold, поэтому
миграция работает и при следующем входе отсутствовавшего игрока. Усталость/S
ограничиваются актуальными границами. После изменения состава дерева переоткройте
экран. Редактирование условий не отзывает уже открытый узел; его эффект определяется
актуальной конфигурацией. Тексты переводов находятся в assets/faustcore/lang. schema=1 при чтении автоматически мигрирует в schema=2: S масштабируется ×0.2, F из доли переводится в единицы нового B, прежние покупки +5 сохраняют достигнутый предел, но не выше 20. Legacy progression.json распознаётся по purchaseGrowth; изменяемые JSON копируются в migration-v1 перед обновлением формул и ресурса. Миграция рассчитана на согласованный масштаб ресурса 100→20; пользовательские значения соответствующих ставок также масштабируются. Дополнительно сохраните резервную копию рабочего мира до обновления.

## Панель, клавиша и команды (1.1)

Вкладки над Survival-инвентарём переключают InventoryScreen и CoreScreen.
InventoryScreenMixin использует реальные leftPos/topPos, включая сдвиг книги
рецептов. Обзор — две колонки по три карточки с иконками и описаниями; нажатие
открывает описание навыка и его дерево (две способности на страницу). Это свой
код раскладки с неизменёнными спрайтами источника, без переноса титулов, Magic/Luck.
K — зарегистрированная KeyMapping `key.faustcore.skills`, категория
`key.categories.faustcore`. Игрок переназначает её в Controls; значение сохраняет
Minecraft в options.txt. Старый client.openKey больше не используется.

Обычные команды: `/core` или `/core help`, `/core status`, `/core cap <skill>`
(алиас `/core cap buy <skill>`), `/core unlock <ability>`, `/core path <id>`.
Имена skills/abilities дополняются Tab. Цена проверяется по experienceLevel,
ошибки различают неизвестный навык, недостаток уровней, максимум и требования узла.

Администратор (permission level 2) / серверная консоль:

```text
/core status <targets>
/core skill set <targets> <skill> <level>=0
/core skill add <targets> <skill> <signed integer>
/core skill xp <targets> <skill> <practice units>=0
/core cap set <targets> <skill> <0..20>
/core ability grant <targets> <ability>
/core ability revoke <targets> <ability>
/core stamina set <targets> <units>=0
/core stamina fill <targets>
/core fatigue set <targets> <units>=0
/core fatigue clear <targets>
/core reset <targets>
/core reload
```

`targets` — EntityArgument.players: имя или селектор @s/@a и другие подходящие
селекторы. Консоли нужен явный игрок/@a; её @s не обозначает игрока. Администраторские
ресурсные операции ограничиваются текущим M и настройками F; fill не снимает F.
set/add уровня сбрасывают только внутриуровневую практику и threshold, не выдают
узлы автоматически. xp применяет текущий множитель к практике без счётчиков
достижений. cap set сохраняет limitOverride, не расходует XP и не отменяет историю
покупок. ability grant обходит требования; revoke снимает также потомков.
reset полностью заменяет Progress выбранных игроков, включая путь и усталость.
Обычному игроку эти изменения недоступны. Сообщения об административной мутации
возвращают количество обновлённых игроков; каждое изменение синхронизируется.

## Архитектура, стороны и хранение

common/progression — модель без Minecraft-зависимости (Gson для JSON).
common/runtime — серверное соединение модели с Minecraft, транзакции оплаты,
команды, снимки. common/api — серверный API; модель Progress и схема изменились в 1.1. common/client — экран и HUD.
common/mixin — vanilla hooks, одинаковые для обоих загрузчиков. client Mixin
указаны только в секции client. Ни common model, ни серверные hooks не обращаются
к net.minecraft.client. NeoForge клиентский сетевой обработчик изолирован во
вложенном клиентском классе и подключается только при Dist.CLIENT.

Fabric/NeoForge содержат регистрацию payload/команд и реализацию IPlatformHelper.
ServiceLoader ищет com.faust.core.platform.services.IPlatformHelper; каждый JAR
включает свой META-INF/services с соответствующим провайдером.
Общий код не импортирует API загрузчиков. Architectury не подключён.

ServerPlayerMixin хранит Progress у игрока. В vanilla player NBT находится строка
faustcore с JSON schema=2: tracks (L, x, число покупок, последний threshold, необязательный limitOverride для администраторского cap set),
counters, unlocked, discoveries, purchases G, revision, stamina S, fatigue F, path.
Неизвестная версия/испорченная запись вызывает явную ошибку вместо тихого обнуления.
Жизненный цикл restoreFrom копирует данные, включая усталость; модификаторы
переустанавливаются с постоянными ID faustcore:strength и faustcore:dexterity,
не складываются заново при входе. Кратковременные лимиты сессии сбрасываются при
выходе/возрождении; Constitution от этих лимитов не зависит.

Сервер — единственный источник прогресса. Клиентские кнопки отправляют обычные
команды намерения, не цену или итоговый уровень. Команды исполняются в серверном
потоке. Оплата и изменение предела последовательны; недостаток XP ничего не меняет.
Открытие узла повторно отклоняется. API выдаёт копию Progress через snapshot,
а не прямую ссылку на сохранение.

Сеть v2 (NeoForge registrar 2): S2C faustcore:snapshot (Progress, параметры Balance при первом сообщении
и их изменении, vanilla-уровни кошелька, нагрузка брони); C2S faustcore:swim_input (boolean
намерения идти вперёд, каждые 5 клиентских тиков). Полный публичный снимок каждые
5 серверных тиков; личная история discoveries клиенту не отправляется. Это пока
снимки, не delta-протокол. Minecraft transport надёжен; отдельного ACK/revision
recovery протокола нет. Команда /core теперь показывает помощь; обычные снимки продолжают приходить автоматически. Прогресс и
настройки принимаются только от сервера, счётчики действий с клиента не читаются.
Протокол не предназначен для клиента без core. Ограничение строк payload — 262144
символа; очень большие пользовательские конфиги требуют контроля размера.

## Публичный API и минимальная интеграция пути (1.1)

API: com.faust.core.api.CoreApi, модели Skill, Balance, Progress. Серверные операции
нужно вызывать только в потоке соответствующего MinecraftServer. Регистрации
выполняются один раз при инициализации мода, до начала игровых событий.

| Операция | Контракт |
|---|---|
| registerSkill(String namespacedId) → Skill | Добавить навык; повторная явная регистрация запрещена. Шесть встроенных ID сохраняются короткими для совместимости сохранения |
| registerBonus(String id, BiConsumer<ServerPlayer,Double>) | Серверный обработчик эффекта дерева; вызывается при пересчёте атрибутов (раз/с и reload), в том числе с 0. Обработчик обязан заменить/снять свой модификатор, а не накапливать его |
| registerPath(String id, Predicate<ServerPlayer>) | Уникальный путь с серверным условием выбора; встроенных путей нет |
| paths() | Копия множества зарегистрированных путей |
| meets(ServerPlayer, Skill, int) | Проверка уровня основного навыка |
| snapshot(ServerPlayer) → Progress | Отдельная копия данных; её изменение не влияет на сервер |
| grantAction(ServerPlayer, String action, double units, double count) | Подтверждённое адаптером действие; units×xp даёт X, count увеличивает counter. Неизвестное/отменённое действие возвращает false |
| beforeProgress(ToDoubleFunction<Grant>) | Событие до изменения; обработчики в порядке регистрации, 0 отменяет, коэффициенты перемножаются с верхним ограничением 100 |
| afterProgress(Consumer<Change>) | После зачёта: UUID игрока, action, JSON до/после. Изменять эти JSON бесполезно для сохранения |
| choosePath(ServerPlayer,String) | Только первоначальный выбор пустого path с проверкой Predicate; повтор/смена отклоняются. Экономика смены пути ещё не определена |

Grant содержит player, action, units, count. Коэффициент каждого before-handler
должен быть конечным 0…100. Повторный grantAction из обработчика того же игрока
отклоняется, чтобы исключить рекурсию. Ошибки стороннего обработчика не подавляются;
расширение отвечает за свой код. События прогресса не являются событиями покупки
или открытия узла и не возникают у клиента от одного обновления HUD.

DefenseKind перечисляет SHIELD_BLOCK, WEAPON_BLOCK, PARRY, DODGE для будущего
контракта адаптера. Самого подключения сторонней боевой системы пока нет. Ядро
сейчас считает только vanilla-щит. В будущем адаптер должен различать блок щитом,
оружием, парирование и уклонение, исключать повтор атаки, использовать серверный
результат и согласовать владельца выносливости. Ни Epic Fight, ни Advanced Fight +
Dodge, ни Create не заявлены как уже совместимые зависимости. Ручной привод Create,
развивающий Strength, остаётся будущей интеграцией.

Минимальная регистрация пути в init внешнего мода:

```java
import com.faust.core.api.CoreApi;
import com.faust.core.progression.Skill;

// Это пример интеграции, не реализованный путь ядра.
CoreApi.registerPath("examplepath:scholar", player ->
    CoreApi.meets(player, Skill.intelligence, 5));

// В обработчике подтверждённого серверного выбора:
boolean selected = CoreApi.choosePath(serverPlayer, "examplepath:scholar");
// То же действие доступно через /core path examplepath:scholar.
```

Для собственного навыка: зарегистрируйте CoreApi.registerSkill("examplepath:lore").
В actions.json сервера добавьте, например:

```json
"examplepath:study": {
  "skill": "examplepath:lore",
  "xp": 2.0,
  "counter": "examplepath:studies"
}
```

В подтверждённом серверном событии вызовите
`CoreApi.grantAction(player, "examplepath:study", 1, 1)`.
Только адаптер определяет реальность действия; клиент не должен вызывать выдачу.
Свой узел добавляется в abilities.json с уникальным namespaced id и настроенными
level/counter/amount/parent/effect/value. Для нового эффекта зарегистрируйте
registerBonus. При удалении мода его неизвестные ID остаются в данных, но бонус
не применяется без обработчика. Переводы и клиентский интерфейс расширения
поставляет внешний мод; текущий экран оптимизирован под шесть основных вкладок,
для большого числа добавочных навыков потребуется расширение навигации.

Подключение из соседнего проекта: соберите core, затем используйте локальную
Gradle-публикацию Maven (конвенция проекта берёт путь из local_maven_url) либо
loader-specific JAR как локальную зависимость. Готового удалённого Maven нет.
Для Fabric используйте modImplementation files("libs/faustcore-fabric-1.21.1-1.4.0.jar"),
для NeoForge — implementation files("libs/faustcore-neoforge-1.21.1-1.4.0.jar") в
совместимом ModDev-проекте; common для компиляции можно подключить как compileOnly
files("libs/faustcore-common-1.21.1-1.3.0.jar"). Не встраивайте JAR ядра в JAR пути;
пользователь устанавливает его отдельно. В fabric.mod.json укажите depends.faustcore,
в neoforge.mods.toml — required dependency faustcore, обе стороны, совместимую
версию (для текущего контракта 1.1.0). Для новой версии API сначала проверить
совместимость, не обещать вечную бинарную совместимость.

## Сборка, тесты и игровой чек-лист

Gradle Wrapper, JDK 21. ./gradlew.bat build собирает common, Fabric и NeoForge;
:common:modelTest выполняет отдельный Java regression runner без JUnit. Тестовая
инфраструктура теперь существует; модельные проверки не запускают игровой мир.
Проверяются формулы, дробный опыт и разбиение, общий G и неуспешная покупка,
условия/предшественники/повторное открытие, snapshot persistence, offline миграция
threshold, усталость/сон/костёр/отключение, цикл конфигурации, дубли регистраций,
масштабирование/отмена/уведомление API. Для тестов используется уже применяемый
Minecraft Gson 2.10.1, новых runtime-библиотек нет.

Запуски:

```powershell
./gradlew.bat :fabric:runClient
./gradlew.bat :neoforge:runClient
./gradlew.bat :fabric:runServer
./gradlew.bat :neoforge:runServer
```

Dev Fabric хранит клиент/сервер в fabric/runs/client и fabric/runs/server.
NeoForge по текущей конвенции использует neoforge/run; не запускайте два экземпляра
одновременно в этом каталоге. Для проверки multiplayer создайте отдельные игровые
инстансы с JAR и своим миром. EULA принимает владелец. На dedicated server не должны
загружаться CoreClient/CoreScreen/клиентские Mixin.

Ручная приёмка на обоих загрузчиках: все действия таблицы, пустое/отменённое действие,
полный/частичный блок, смертельный урон, достигнутый мягкий предел, две покупки
разных веток, недостаток XP, дважды открытый узел, броня ниже/выше H, стоячая/текущая
вода, исчерпание S, сон с пропуском ночи, костёр горящий/потухший, смерть/возрождение,
reconnect/restart/измерение, смена баланса и ошибочный reload, отключение ресурса и
только усталости. Проверяйте числа до и после через K и конфиги тестового экземпляра.
README содержит удобные пошаговые команды и сценарии для владельца.

Актуальная приёмка 1.1: формулы и миграции проверяются модельным runner; команды
проверяются настоящим парсером Brigadier с bootstrap Minecraft, включая selectors,
namespaced ID, диапазоны аргументов, подсказки и права normal player/OP.
NeoForge dev-клиент вошёл в тестовый мир без ошибки загрузки. Полная визуальная
приёмка нового экрана не выполнена: захват окна завершился FrameArrived timeout,
после обнаружения пользовательского ввода управление ему оставлено. Журналы
старта и успешная сборка не заменяют ручную проверку всех игровых сценариев.
Ручной чек-лист и готовые команды приведены в README.

## Назначение и контекст

- Это ядро серии модов Minecraft Java 1.21.1 для Fabric и NeoForge на основе MultiLoader-Template. Используется JDK 21 и Gradle Wrapper. Имя Gradle-проекта — `core`.

## Структура и архитектура

- `common/` — общая игровая логика, интерфейсы платформы, общие Mixin и ресурсы. Не добавляй сюда прямые зависимости от API Fabric или NeoForge.
- `fabric/` и `neoforge/` — точки входа, реализации интерфейсов платформы, регистрация и другие особенности соответствующего загрузчика.
- Платформенные возможности предоставляй через интерфейсы в `common` и реализации в модулях загрузчиков. В существующей архитектуре используется `ServiceLoader`; при изменении сервисов проверяй имена и содержимое файлов `META-INF/services` обеих платформ.
- `buildSrc/` содержит общие Gradle-конвенции. Изменения здесь проверяй для обоих загрузчиков. Подстановка метаданных ресурсов настроена в `buildSrc/src/main/groovy/multiloader-common.gradle` через `expandProps`.
- Клиентские классы, рендеринг и обращения к `net.minecraft.client` не должны загружаться на dedicated server. Проверяй сторону выполнения, включая Mixin и статическую инициализацию.
- При дальнейшем переименовании мода согласованно обновляй `gradle.properties`, пакеты, точки входа, пространства имён ресурсов, метаданные загрузчиков, конфигурации Mixin и `META-INF/services`.
- Изменяя ресурсы, проверяй идентификаторы, пути, JSON/TOML, ссылки на текстуры, модели, переводы и данные. Общие ресурсы размещай в `common`, платформенные — в соответствующем модуле.
- Новые библиотеки подключай только для конкретной задачи с проверкой совместимости с Minecraft 1.21.1 и обоими загрузчиками. GeckoLib пока не подключена.
